# 领域边界

归集铁路、公路、水路、民航假期客流，处理口径差异、迟到修订、勘误发布与历史解释。

## 核心对象

- 来源机构（Source）：铁路/公路/水路/民航数据提供方，每个口径归属唯一来源。
- 统计口径（Caliber）：component 为直接采集分项，aggregate 为分项合计；
  公路 aggregate = 公路营业性客运 + 非营业性小客车出行。
- 覆盖日期：批次逐日值必须落在假期窗口内。
- 原始批次（Batch）：只追加、不可篡改；修订产生新批次并把旧批次置为 superseded。
- 修订原因：任何修订批次必须填写原因并随批次留痕。
- 发布版本（Publication）：不可变快照；已发布版本只能通过勘误衔接新版本，不得原地覆盖。

## 归集与校验规则

1. 单位先归一化：支持万人次、人次、亿人次，内部统一为万人次；
   同一内容以不同单位报送仍判为重复。
2. 同一来源同一批次编号、内容相同 → 判重（duplicate），不重复累计。
3. 同一来源同一批次编号、内容不同且未显式声明修订 → 隔离（quarantine），
   不计入任何指标，必须由人工裁决 accept/reject 并记录说明。
4. 显式修订（revision_of + revision_reason）必须覆盖原批次全部日期；
   旧批次 superseded，修订批次接替。
5. 包含关系：公路合计逐日值必须等于营业性 + 小客车（容差 0.05 万人次）。
   校验在写入事件**之前**试算，不成立则整笔拒绝并留 rejected 记录，状态不被污染；
   发布前对全部合计口径再强制校验一次。
6. 派生指标：日均 = 总量/假期天数；可比增幅按日均比较，兼容假期天数不同；
   无上年基数时增幅为 None，不臆造。
7. 增量重算：每个派生指标带输入指纹，补报只重算指纹变化的
   「口径 → 方式 → 全国」链路，其余指标不产生新事件。

## 人工调整

- 人工调整（口径级须指定日期；另有全国级）提交后为 pending，不生效。
- 必须由**另一名人员**复核；提交人复核自己的调整一律拒绝。
- 复核通过前先试算包含关系，破坏包含关系的调整不得批准。
- 批准的调整随发布快照留痕（提交人、复核人、原因、金额）。

## 发布、勘误与解释

- publish 生成不可变版本快照：指标值、采用批次清单、已批准调整、
  待确认口径、隔离批次。
- issue_corrigendum 基于当前状态发布新版本，记录 supersedes 与勘误原因。
- explain_version 可对任一历史版本回答：总量采用了哪些批次、
  哪些数据仍待确认、与上一公报在指标与批次层面的差异及原因。

## 截止期与恢复

- 口径可设截止期；pending_reminders 给出临期/逾期且未报齐的口径，
  以及临期/逾期的待发布任务；fire_due_reminders 留痕且按缺失状态去重，
  数据补齐或缺失集合变化后可再次提醒。
- 所有状态变更写入追加式事件日志（events.logl），周期性原子快照加速重启；
  服务重启构造服务即完成回放恢复，resume() 续跑待发布任务、
  隔离裁决、待复核调整与提醒。

资料版本只能递增。参与方、事实和约束均不能为空，示例不得包含真实个人信息、账号或凭据。
